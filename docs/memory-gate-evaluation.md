# Kev / Laya 记忆交互判断实测（2026-09-22）

**优先选 Kev 做 shadow 试点，首先观察记忆提案判断；两者目前都不适合独立决定跳过检索或自动写入。** Kev 的优势主要来自写入分类，读取原始分类并未胜过 Laya。客户端任务入口与调用计量的收益优先于更换模型。

## 方法

- 固定 60 条人工编写、开发者自标注的合成中文用例，读取和写入各 30；其中 48 条为语义判断、12 条为显式控制/敏感信息边界。没有使用真实用户记忆或对话。
- 同一请求协议、判定说明和候选标签，逐条交错、串行请求两个服务。Kev 使用本机 RTX 2080 Ti / FP16，Laya 使用 CPU / FP32 / 4 线程；这里比较的是这两个部署的表现，并非相同算力下的模型速度。
- `model`：48 条语义用例的原始分类，不用业务规则或阈值；`gate`：60 条用例的完整规则+模型+兜底链，阈值 0.8，总超时 2 秒。
- 初版说明漏列了长期项目事实，已按业务契约补齐后重测，没有修改用例标签。最终版本再反转候选选项顺序做敏感性检查；未针对测试结果调整阈值或启用自动执行。
- 数据集虽包含 `dev` / `holdout` 字段，但本轮已观察全体结果、标签非独立评审，不能称为生产准确率或独立盲测。只测短中文输入；未测长输入质量、真实任务分布、吞吐和资源成本。

可复核数据：[逐条决策与统计 JSON](evals/memory-gate-20260922.json)；用例：[60 条合成场景](../tests/fixtures/memory_gate_cases.json)；复验入口：[eval_memory_gate.py](../scripts/eval_memory_gate.py)。JSON 保留数据集哈希和模型请求提示哈希；模型 revision 分别为 Kev `485ace8703592fcf405488b262449990824cfed1`、Laya `052592a15d198d9ad47da779604259b10b47b7aa`。

## 原始模型分类

| 指标 | Kev-4B | Laya multilingual |
|---|---:|---:|
| 总命中 | **35/48（72.9%）** | 25/48（52.1%） |
| 读取分类 | 14/24（58.3%） | **16/24（66.7%）** |
| 写入分类 | **21/24（87.5%）** | 9/24（37.5%） |
| 应读取却判 skip | 10/12 | 7/12 |
| 不应提案却判 propose | 1/12 | 4/12 |
| HTTP 延迟 P50 | 236 ms | 254 ms |
| HTTP 延迟 P95 | 288 ms | 328 ms |
| 接口错误/超时 | 0/48 | 0/48 |

读取误判说明：有些模型把“继续集成那个服务”“兼容现有账号体系”等任务视为当前信息足够。这恰好会放大 EchoMe 当前的漏调用问题。写入中的 `propose` 只代表值得生成待审提案，不等于提案内容正确、去重成功或可自动入库。

## 完整 Gate 建议

| 指标 | 规则基线 | 规则+Kev | 规则+Laya |
|---|---:|---:|---:|
| 总命中（含控制用例） | 28/60（46.7%） | **49/60（81.7%）** | 36/60（60.0%） |
| 读取分类 | 18/30 | **28/30** | 23/30 |
| 写入分类 | 10/30 | **21/30** | 13/30 |
| 应读取却建议 skip | 0/14 | 2/14 | 3/14 |
| 不应提案却建议 propose | 0/16 | 0/16 | 1/16 |
| 因低概率回退 | 0 | 21 | 20 |
| 真实模型调用 | 0 | 47 | 47 |
| 全链路 P95 | <1 ms | 651 ms | 330 ms |

规则基线读取宁可多查，写入不确定则 review，因此命中率低却没有这批样例中的危险误建议。加上保守回退后，Kev 的综合效果较好；但 21 条低概率回退并非模型成功，不能把 81.7% 解释成模型准确率。

Kev 剩余漏读为 `read-11`（新增登录且兼容现有账号）、`read-12`（服务可用后继续集成），模型 skip 概率均为 0.8。Laya 对 `write-22`（“把查询速度再提高一些就好了”）以约 0.9594 的概率建议 propose，而标注为意图不清需 review，说明高概率也可能错。默认 0.8 是试点配置，尚未做业务校准。

Gate 与 model 延迟分别来自独立请求序列，Gate 含规则命中和回退；两列不是同一个样本集合，不能把差值当作稳定的软件开销。最终两种模式的 190 次真实模型请求均没有观察到接口错误，这不代表长期可用性保证。

## 选项顺序检查

| 原始模型分类 | Kev | Laya |
|---|---:|---:|
| 标准顺序命中 | 35/48 | 25/48 |
| 反序命中 | 39/48 | 22/48 |
| 相对标准顺序的答案变化 | 6/48 | 11/48 |

反序之后 Kev 总命中上升，Laya 下降；不能选一个更好看的顺序就声称问题解决。这里的变化包含可能的运行波动，未额外进行相同输入多轮重复来分离随机性；结果已经足以要求后续固定模板并验证稳健性。

初版契约下原始命中为 Kev 29/48、Laya 25/48；最终契约为 35/48、25/48。说明任务描述会影响结果，不能依据通用三问演示的表现直接决定生产模型。

## 下一步

1. 优先交付 context 预算修复和 Gate shadow 工具；这些工作不依赖模型已达到自动执行标准。
2. 客户端任务入口先提供可靠触发与完整计量：顶层任务数、判定数、context 尝试数、正文交付量和实际使用反馈。模型没有收到任务时，再高的分类能力也无法补回调用。
3. Kev 作为下一阶段默认对比候选，Laya 保留 CPU 备选。先人工标注真实的、去除敏感信息的任务摘要，扩充“不该漏读”和“不能误存”的边界样例；使用新的留出数据评估阈值。
4. 读取端保留规则与显式用户意图，失败时继续检索；写入端建设独立提案箱。当前 `ai_review` 已参与检索，不能用于隔离模型提案。
5. 观察结果通过后，再逐类开放自动读取和受控写入；当前代码、测评和文档均不代表客户端 Hook 或自动入库已上线。

完整实施顺序见 [Memory Gate 试点](memory-gate.md)。
